# OBP frame relay

Ticket-gated **hub relay** for OBP negotiation byte streams: stamp optional `RelayEnvelope`, fan out opaque frames, and spool them for late joiners.

## Layout

| Path | Package |
|------|---------|
| `spec/model/` | `@khoralabs/obp-frame-relay-spec` — `RelayEnvelope` wire policy + `FrameRelayStore` persistence service |
| `impl/ts/` | `@khoralabs/obp-frame-relay` — hub runtime, store strategy port, in-memory adapter, Bun WS helpers |
| `sqlite/` | `@khoralabs/obp-frame-relay-sqlite` — reference SQLite `FrameRelayStoreStrategy` |

## Admission tickets (mandatory)

Channel join proofs are HMAC-SHA256 tickets generated by the hub at channel creation time. The ticket utilities live in `@khoralabs/duplex-byte-stream` (`generateChannelSecretHex`, `signChannelTicket`, `verifyChannelTicket`).

**Network deployments MUST verify tickets before attaching peers.** Without a verified ticket, anyone who knows a `channelId` can join, receive the full replay, and inject frames.

1. Create a channel: `const { ticket } = await hub.createChannel(channelId)`
2. Deliver `ticket` to authorized peers out-of-band (your product layer)
3. On WebSocket upgrade, call `upgradeFrameRelayHubWebSocket({ req, channelId, ticket, hub, upgrade })` before `frameRelayHubWebSocketHandlers` runs
4. For in-process duplex attach, pass the same ticket to `attachDuplexAsFrameRelayPeer(hub, channelId, ticket, duplex)`

`attachPeer` rejects invalid or expired tickets at the hub layer (defense in depth).

### Browser WebSocket hardening (required for browser-facing relays)

Ticket verification alone does **not** stop cross-origin WebSocket CSRF when a victim browser can reach a ticket URL. Browser deployments **must** also:

1. **`allowedOrigins`** — pass your site origin(s) to `upgradeFrameRelayHubWebSocket` so the `Origin` header is checked before upgrade.
2. **`requireTls: true`** — when the upgrade `Request` reflects HTTPS (or TLS-terminated `x-forwarded-proto`).
3. **`authorize`** — optional hook for principal binding, invite tokens, rate limits, etc.
4. **`onOpen`** on `frameRelayHubWebSocketHandlers` — optional defense-in-depth before `attachPeer`.

Daemon clients often omit `Origin`; leave `rejectMissingOrigin` unset unless the endpoint is browser-only.

```ts
import {
  frameRelayHubWebSocketHandlers,
  upgradeFrameRelayHubWebSocket,
} from "@khoralabs/obp-frame-relay";

const wsHandlers = frameRelayHubWebSocketHandlers({
  hub,
  onOpen: async ({ sessionId, ticket }) => myPolicyAllows(sessionId, ticket),
});

// In fetch handler:
return upgradeFrameRelayHubWebSocket({
  req,
  channelId,
  ticket,
  hub,
  allowedOrigins: ["https://app.example.com"],
  requireTls: true,
  authorize: async (ctx) => rateLimiter.allow(ctx),
  upgrade: (upgradeReq, data) => server.upgrade(upgradeReq, { data }),
});
```

## Bounded spool and replay

Per-channel spool uses a ring buffer (defaults: 1024 frames / 16 MiB). Replay on attach is capped to the most recent tail (defaults: 1024 frames / 8 MiB). Pass `replayAfterFrameId` to `attachPeer` for incremental catch-up.

```ts
import {
  DEFAULT_FRAME_RELAY_SPOOL_LIMITS,
  startFrameRelayPurgeInterval,
} from "@khoralabs/obp-frame-relay";

const hub = createFrameRelayHub({ store, spoolLimits: DEFAULT_FRAME_RELAY_SPOOL_LIMITS });
const stopPurge = startFrameRelayPurgeInterval(hub, 5 * 60_000); // every 5 min
```

Long-running daemons SHOULD call `hub.purgeExpiredChannels()` periodically (or use `startFrameRelayPurgeInterval`).

## SQLite pairing secret encryption

The reference SQLite store encrypts `rooms.pairing_secret_hex` with AES-256-GCM. Pass a 32-byte key when creating the strategy:

```ts
import {
  createSqliteFrameRelayStoreStrategy,
  pairingSecretKeyFromEnv,
  restrictRelayStoreDatabasePermissions,
} from "@khoralabs/obp-frame-relay-sqlite";

const dbPath = "/var/lib/obp/relay.sqlite";
restrictRelayStoreDatabasePermissions(dbPath);
const store = createSqliteFrameRelayStoreStrategy(db, {
  pairingSecretKey: pairingSecretKeyFromEnv(),
});
```

Set `OBP_PAIRING_SECRET_ENCRYPTION_KEY` in production (64-char hex or ≥32-byte UTF-8). See [SECURITY.md](../../SECURITY.md).
